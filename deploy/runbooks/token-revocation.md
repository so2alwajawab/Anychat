# دليل التشغيل: إدارة دورة حياة الرموز وإعادة المصادقة (Token Revocation Runbook)

## الهدف
التعامل مع حالات انتهاء صلاحية أو إلغاء رموز وصول Meta (Page Access Token / User Token) واستعادة الربط بسلاسة.

---

## الأعراض والأسباب المحتملة لإلغاء الرمز (Meta Error Code 190)
- قيام مالك الصفحة بتغيير كلمة مرور حسابه الشخصي على فيسبوك.
- قيام مالك الصفحة بإلغاء إذن التطبيق من إعدادات الأمان في فيسبوك.
- انتهاء فترة صلاحية الرمز التلقائية بعد 60-90 يوماً.
- قيام فيسبوك بطلب إعادة تحقق أمني من المستخدم.

---

## كيف يكتشف النظام الحالة تلقائياً
1. عند فشل أي استدعاء Graph API بكود خطأ `190` أو `200`، تقوم دالة `OutboundService` فوراً بتحديث حالة الأصل في قاعدة البيانات:
   ```sql
   UPDATE meta_connected_asset SET connection_status = 'reauth_required' WHERE id = '<asset_id>';
   ```
2. تسجل المنصة تلقائياً حدثاً في سجل التدقيق الأمني: `meta.asset.health` مع سبب `token_invalid_or_expired`.
3. يظهر شريط تنبيه أحمر بارز في لوحة التحكم العلوية وفي صفحة الاتصالات `/connections` ينبه المالك بضرورة إعادة الربط.
4. يتم تعليق مسارات الأتمتة التابعة للأصل تلقائياً لتجنب تسجيل محاولات فاشلة متكررة تؤدي إلى حظر الحساب من ميتا.

---

## خطوات إعادة الربط والمصادقة (Reconnection Procedure)
1. يسجل المالك دخوله إلى AnyChat عبر `https://anychat.egyptcamp.cloud`.
2. ينتقل إلى صفحة **«اتصالات ميتا» (`/connections`)**.
3. يضغط على زر **«إعادة الربط»** بجوار الصفحة المتأثرة، أو يضغط على **«الاتصال عبر فيسبوك»** في أعلى الصفحة.
4. يُعاد توجيهه إلى نافذة فيسبوك الرسمية لتأكيد الصلاحيات.
5. يستلم النظام الرمز الجديد تلقائياً، ويقوم بتشفيره بـ AES-256-GCM، وتحديث حالة الأصل إلى `connected` وإعادة تفعيل الأتمتة مباشرة دون الحاجة لأي تدخل يدوي في الخادم.
